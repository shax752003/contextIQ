INDUSTRIAL DOCUMENT MULTIMODAL RAG SYSTEM
=========================================
Generated Documentation Report

1. EXECUTIVE SUMMARY
--------------------
This project implements a production-grade functional Retrieval-Augmented Generation (RAG) system specifically optimized for complex industrial documents. Unlike standard RAG implementations that treat PDF content as a single stream of text, this system recognizes and processes different modalities—text, tables, images, and scanned OCR content—independently to preserve semantic structure and context.

The system has been hardened for production environments with features like data versioning, idempotent execution pipelines, deterministic chunk hashing, and strict read-only application logic.

2. PROBLEM STATEMENT
--------------------
Standard RAG pipelines fail on industrial technical documents (e.g., datasheets, manuals) because:
- Tables are flattened into incoherent strings, losing row/column relationships.
- Images and diagrams (crucial for technical context) are ignored.
- Scanned pages (OCR) introduce noise and are often chunked poorly.
- Duplicate processing wastes compute and storage.
- Lack of strict separation between "training/indexing" and "serving" leads to production risks.

3. SOLUTION ARCHITECTURE
------------------------
The system is divided into two strict logical domains:
1. PIPELINES (Write Access): Heavy-duty offline processing to ingest, extract, chunk, and index data.
2. APP (Read-Only): Lightweight online service to query the index and generate answers.

4. KEY FEATURES & IMPLEMENTATION DETAILS
----------------------------------------

A. Multi-Modal Extraction (pipelines/extract.py)
   - Text: Extracted via `Docling` for high-fidelity structural understanding.
   - Tables: Processed via `Camelot` to retain CSV-like structure, preventing "table soup."
   - Images: Extracted via `PyMuPDF` and `PDF2Image`.
   - OCR: Scanned pages processed via `Tesseract`.
   - Idempotency: The extractor checks for existing artifacts (`_docling.json`) to skip unnecessary re-processing.

B. Deterministic Chunking & Deduplication (pipelines/chunk.py, pipelines/embed.py)
   - Every chunk is assigned a purely deterministic SHA-256 hash based on its content, source file, and page number.
   - The Embedding pipeline checks the Vector DB for existing hashes before calculating embeddings.
   - Result: Zero duplicate vectors, 100% stable index even after re-runs.

C. Production Hardening (Phase 3 & 4)
   - Data Versioning: Data stored in `data/{version}/` (controlled via `DATASET_VERSION` env var).
   - Manifest Tracking: `pipeline_metadata.json` records every pipeline run, status, and configuration.
   - Configuration: Centralized in `app/config.py`, powered by `.env` (python-dotenv).
   - Read-Only App: `app/retrieval.py` enforces a strict check to ensure it never attempts to write to the Vector DB or create indices, preventing concurrency issues in execution.

D. Deployment
   - Dockerized: Full support via `Dockerfile` for reproducible builds.
   - Entry Point: `main.py` serves as a clean CLI entry point that handles secure API key injection (loading `.env` or prompting user).

5. TECH STACK
-------------
- Language: Python 3.10+
- Orchestration: Custom Modules (`pipelines/run_all.py`)
- LLM: OpenRouter API (Google Gemma 2 27B / compatible)
- Embeddings: HuggingFace (sentence-transformers/all-MiniLM-L6-v2)
- Vector DB: ChromaDB (Persistent)
- PDF Engines: Docling, PyMuPDF, PDF2Image
- OCR Engine: Tesseract
- Table Engine: Camelot

7. HOW TO RUN
-------------
1. Setup Environment:
   cp .env.example .env
   (Add OPENROUTER_API_KEY)

2. Run Pipeline (Ingest -> Extract -> Chunk -> Embed):
   python -m pipelines.run_all

3. Query System:
   python main.py
